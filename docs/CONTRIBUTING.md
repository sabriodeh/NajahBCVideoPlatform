# أسلوب العمل على المشروع

## ⚠️ القاعدة الأهم

**أي دمج في `main` يُنشر فوراً على الموقع العلني.**

لا توجد بيئة تجريبية (staging) ولا خطوة موافقة يدوية: الدفع إلى `main` يشغّل
`deploy.yml` الذي يبني ويدفع إلى `gh-pages` مباشرة. لذلك:

- لا تدفع إلى `main` مباشرة — اعمل على فرع وافتح Pull Request.
- لا تعدّل فرع `gh-pages` إطلاقاً — محتواه ناتج بناء يُعاد توليده آلياً.

---

## دورة العمل

```bash
# 1. ابدأ من main محدّث
git checkout main && git pull

# 2. افتح فرعاً
git checkout -b feat/short-description

# 3. اعمل، ثم تحقّق قبل الدفع
npm run check        # lint + build

# 4. ادفع وافتح PR
git push -u origin feat/short-description
```

---

## تسمية الفروع

| البادئة | الاستخدام |
| --- | --- |
| `feat/` | ميزة جديدة |
| `fix/` | إصلاح خلل |
| `chore/` | صيانة، إعدادات، توثيق، تبعيات |
| `refactor/` | إعادة هيكلة دون تغيير السلوك |

أمثلة: `feat/video-search`، `fix/drive-thumbnail-timeout`،
`refactor/split-app-jsx`.

---

## رسائل الـ commit

السجل الحالي يستخدم العربية، والاستمرار على ذلك مقبول. المطلوب فقط:

1. سطر أول قصير يصف **ما تغيّر** (≤ 72 محرفاً).
2. فقرة تشرح **لماذا** إن لم يكن السبب بديهياً.
3. commit واحد لكل تغيير منطقي — لا تخلط إعادة الهيكلة بتغيير السلوك.

يمكن اختيارياً استخدام بادئة إنجليزية (`feat:`، `fix:`، `chore:`) مع بقية
الرسالة بالعربية، كما في هذا المستودع.

## قبل فتح الـ PR

- [ ] `npm run check` ينجح دون أخطاء.
- [ ] لم أزد عدد تحذيرات oxlint (يوجد حالياً تحذيران معروفان في
      `App.jsx:405` و`App.jsx:684`).
- [ ] جرّبت التغيير فعلياً عبر `npm run dev`.
- [ ] لم أُدخل أسراراً حقيقية (كلمات مرور، مفاتيح `service_role`) في الكود.
- [ ] حدّثت `docs/` إن تغيّرت البنية أو نموذج البيانات.

## ما يستحق انتباهاً خاصاً

### مفاتيح Supabase
لا تُفرغ `SUPABASE_URL` أو `SUPABASE_ANON_KEY`. القيمة الفارغة **لا تُسقط
البناء** — بل تُحوّل الموقع العلني صامتاً إلى وضع عرض ببيانات وهمية:

```js
const DEMO = !SUPABASE_URL || !SUPABASE_ANON_KEY;
```

### قيمة `base`
`base: '/NajahBCVideoPlatform/'` في `vite.config.js` مرتبطة باسم المستودع. أي
تغيير في الاسم يستلزم تحديثها وإلا تعطّلت كل الأصول بعد النشر.

### ملف `.github/workflows/`
تعديل ملفات سير العمل يتطلب صلاحية `workflow` على الرمز (token). إن رُفض الدفع
بسبب ذلك، شغّل:

```bash
gh auth refresh -s workflow
```
