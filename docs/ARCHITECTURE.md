## 1. نظرة معمارية

```
┌──────────────────────────────┐
│  المتصفح                     │
│  React 19 SPA (src/App.jsx)  │
└───────┬──────────────┬───────┘
        │              │
        │ REST + Auth  │ iframe / thumbnail
        ▼              ▼
┌────────────────┐  ┌──────────────────┐
│   Supabase     │  │  Google Drive    │
│  auth + جداول  │  │  ملفات الفيديو   │
└────────────────┘  └──────────────────┘
```

**لا يوجد خادم خلفي خاص بالمشروع.** التطبيق ملفات ثابتة على GitHub Pages،
يتحدث مباشرة إلى Supabase عبر REST، ويعرض الفيديو من Google Drive.

نتيجة مهمّة: **كل قاعدة تحقق أو صلاحية مكتوبة في الواجهة قابلة للتجاوز.**
الضمان الوحيد الحقيقي هو Row Level Security على مستوى Supabase.

## 2. نموذج البيانات

### جدول `profiles`

| العمود | النوع | الوصف |
| --- | --- | --- |
| `id` | uuid | مطابق لـ `auth.users.id` |
| `username` | text | الاسم المعروض (مثال: `د. محمد ابو عمر`) |
| `role` | text | `admin` أو `uploader` — الافتراضي عند غيابه `uploader` |
| `department` | text | القسم (مثال: `ذكاء الأعمال`) |
| `division` | text | الدائرة (`دائرة الأعمال` / `دائرة الاتصال`) |
| `must_change_password` | bool | يُجبر المستخدم على تغيير كلمة المرور عند `true` |

### جدول `videos`

| العمود | النوع | الوصف |
| --- | --- | --- |
| `id` | uuid | المفتاح الأساسي |
| `owner_id` | uuid | صاحب الجلسة → `profiles.id` |
| `owner_name` | text | اسم الناشر — **منسوخ** وقت الإضافة |
| `department` | text | القسم — **منسوخ** وقت الإضافة |
| `division` | text | الدائرة — **منسوخ** وقت الإضافة |
| `title` | text | عنوان الجلسة |
| `description` | text | الوصف |
| `drive_file_id` | text | معرّف ملف Google Drive |
| `category` | text | أحد: `ورشة تدريبية`، `محاضرة`، `ندوة`، `مشروع طلابي` |
| `published` | bool | `false` عند الإرسال، و`true` بعد موافقة المشرف |
| `created_at` | date | تاريخ الإنشاء |

> ⚠️ **تعارض قائم:** الأعمدة `owner_name` و`department` و`division` تُكتب في
> `videos` عند الإضافة، لكن `listPublished()` (سطر 176) و`listPending()`
> (سطر 198) تقرآنها من `profiles` عبر join وتتجاهلان المنسوخة. الاستثناء
> `listMine()` (سطر 190) — بلا join، فتعرض «جلساتي» وحدها القيم القديمة.
> راجع [ROADMAP.md](ROADMAP.md#7-بيانات-مكرّرة-في-جدول-videos).

## 3. المصادقة والأدوار

- المصادقة عبر Supabase Auth بنمط `password grant`:
  `POST /auth/v1/token?grant_type=password`
- بعد نجاح الدخول يُقرأ ملف العضو من `profiles` ويُدمج مع كائن المستخدم.
- **الحسابات مغلقة** — لا تسجيل ذاتي. تُنشأ من العمادة.
- كلمة المرور المؤقتة = البريد الجامعي. عندها `must_change_password = true`
  فتُحجب كل الشاشات إلى أن يغيّرها العضو.

| الدور | الصلاحيات |
| --- | --- |
| زائر (بلا حساب) | تصفّح ومشاهدة المنشور فقط |
| `uploader` | ما سبق + إضافة جلسة (تدخل قائمة المراجعة) + إدارة جلساته |
| `admin` | ما سبق + شاشة المراجعة: نشر أو رفض (حذف) |

> **حالة الجلسة في الذاكرة فقط** (`useState`) — لا تُحفظ في `localStorage`،
> لذلك أي تحديث للصفحة يُخرج المستخدم.

## 4. الشاشات

يُدار التنقل بمتغيّر `view` داخل مكوّن `App` — لا يوجد router ولا مسارات URL.

| القيمة | المكوّن | الوصول |
| --- | --- | --- |
| `home` | `Home` | الجميع |
| `watch` | `Watch` | الجميع |
| `login` | `Login` | الزوار |
| `pwd` | `ChangePassword` | الأعضاء |
| `add` | `AddVideo` | الأعضاء |
| `mine` | `MyVideos` | الأعضاء |
| `admin` | `Admin` | `admin` فقط |

> نتيجة غياب الـ router: **لا يمكن مشاركة رابط مباشر لجلسة**، ولا يعمل زر
> الرجوع في المتصفح.

## 5. تكامل Google Drive

يُلصق الناشر رابط درايف، ويُستخرج المعرّف عبر `extractDriveId()` الذي يدعم
`/file/d/<id>`، و`?id=<id>`، و`/d/<id>`.

| الغرض | الرابط |
| --- | --- |
| صورة مصغّرة | `https://drive.google.com/thumbnail?id=<id>&sz=w800` |
| مشغّل مضمّن | `https://drive.google.com/file/d/<id>/preview` |

**فحص العلنية** (`checkPublic`): يُحمَّل thumbnail بمهلة 8 ثوانٍ — نجاح التحميل
يعني أن الملف متاح للعموم. فحص استدلالي وليس قاطعاً.

> على الناشر ضبط مشاركة الملف على «أي شخص لديه الرابط — مُشاهِد»، وإلا لن يعمل
> العرض.
