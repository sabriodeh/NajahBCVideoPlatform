# البنية ونموذج البيانات

يصف هذا المستند الحالة الفعلية للمشروع كما هي في الكود.

---

## ١. نظرة معمارية

```
┌────────────────────────────────────────┐
│  المتصفح — React SPA (HashRouter)      │
│  ┌──────────────────────────────────┐  │
│  │ AuthProvider ← الجلسة والدور     │  │
│  │ RequireAuth  ← لا عرض بلا جلسة   │  │
│  │ RequireAdmin ← شاشات الإدارة     │  │
│  └──────────────────────────────────┘  │
└──────┬─────────────────────────┬───────┘
       │ supabase-js             │ iframe
       ▼                         ▼
┌──────────────────┐   ┌────────────────────┐
│ Supabase         │   │ Drive (najah.edu)  │
│ Auth + Postgres  │   │ YouTube (nocookie) │
│ محميّة بـ RLS    │   └────────────────────┘
└──────────────────┘
```

**لا خادم خلفي خاص بالمشروع.** ملفات ثابتة على GitHub Pages تتحدّث إلى Supabase
مباشرة.

النتيجة الحاسمة: **كل فحص صلاحية في الواجهة قابل للتجاوز.** مفتاح `anon` علني،
ومن يستدعي REST مباشرة يتخطّى الواجهة كلها. الضمان الوحيد الحقيقي هو RLS.

## ٢. نموذج البيانات

### `profiles`

| العمود | الوصف |
| --- | --- |
| `id` | مطابق لـ `auth.users.id` |
| `username` | الاسم المعروض |
| `role` | `admin` أو غيره — غير الأدمن عضو عادي |
| `department` / `division` | القسم والدائرة |
| `must_change_password` | يحجب كل الشاشات حتى تُغيَّر |

### `sections` — المواضيع

| العمود | الوصف |
| --- | --- |
| `id`, `slug` | المعرّف، و`slug` يظهر في الرابط |
| `title`, `description` | العنوان والوصف |
| `parent_id` | الأب — شجرة بمستويين |
| `sort_order` | الترتيب |

### `entries` — المداخل

| العمود | الوصف |
| --- | --- |
| `section_id` | الموضوع |
| `title`, `summary` | العنوان والنبذة |
| `instructions` | التعليمات الملزِمة — تُعرض مميّزة بصرياً |
| `agent_url`, `agent_access_note` | رابط الوكيل وكيفية الدخول إليه |
| `video_kind` | `drive` أو `youtube` — قيد يمنع النوع بلا معرّف |
| `video_ref` | معرّف الملف أو الفيديو |
| `links` | JSONB: `[{label, url, kind}]` |
| `sort_order`, `created_by` | الترتيب ومن أنشأه |

`kind` في الروابط ∈ `doc | sheet | slide | form | folder | file | pdf | other`.
لا قيد عليه في القاعدة لأن الحقل JSONB.

السكيما كاملة في [`supabase/migrations/`](../supabase/migrations/).

## ٣. الأمان

الطبقات ثلاث، وأهمّها الأخيرة:

| الطبقة | تمنع | تُتجاوز بـ |
| --- | --- | --- |
| `RequireAuth` / `RequireAdmin` | عرض الشاشات | استدعاء REST مباشرة |
| `sanitizeEntry` و`isSafeHttpUrl` | روابط `javascript:` | لا شيء — تُطبَّق عند العرض وعند الحفظ |
| **RLS** | **الوصول إلى البيانات** | **لا شيء** |

### سياسات RLS

- **لا سياسة لدور `anon` إطلاقاً** ⇒ المجهول يرى صفراً من الصفوف. هذه هي البوابة.
- القراءة لكل مسجّل دخول، والكتابة للأدمن وحده.
- `is_admin()` بـ `SECURITY DEFINER` — لتفادي الاستدعاء الدائري على `profiles`.
- `revoke update` على `profiles` ثم `grant update (must_change_password)` فقط،
  فلا يستطيع عضو ترقية نفسه. والكتابة الإدارية تمرّ عبر `admin_update_profile()`.

### حماية الروابط

`agent_url` و`links[].url` يلصقها الأدمن وتُصيَّر كـ `<a href>`. تُفحص **مرتين**:
عند الحفظ في `EntryForm`، وعند العرض في `sanitizeEntry` و`LinkList` — لأن صفوف
البذرة وأي إدراج يدوي بـ SQL لا تمرّ على النموذج إطلاقاً.

`isSafeHttpUrl` تنزع محارف التحكم **قبل** الفحص، لأن المتصفحات تتجاهلها داخل
المخطط فينفَّذ `java<tab>script:` كـ `javascript:`.

## ٤. المسارات

| المسار | الوصول |
| --- | --- |
| `#/login` | عامّ — الشاشة الوحيدة بلا جلسة |
| `#/change-password` | مسجَّل. إجباري عند كلمة المرور المؤقتة، وفيه مخرج بالخروج |
| `#/` | مسجَّل — لوحة المواضيع |
| `#/section/:slug` | مسجَّل — مداخل موضوع |
| `#/entry/:id` | مسجَّل — المدخل الكامل |
| `#/admin`, `#/admin/new`, `#/admin/edit/:id` | أدمن — محمّلة على الطلب |

`HashRouter` لا `BrowserRouter`: GitHub Pages تعيد 404 لأي مسار عميق.

## ٥. الوسائط

| | يوتيوب | درايف |
| --- | --- | --- |
| التضمين | `youtube-nocookie.com/embed/` | `drive.google.com/file/d/<id>/preview` |
| المصغّرة | `img.youtube.com` — علنية | **لا تعمل** ⇒ غلاف مولَّد |
| زر الفتح الخارجي | موجود | **موجود دائماً** |

**لماذا زر الفتح دائم في درايف:** الملفات مقيّدة على نطاق `najah.edu`. قِسنا أن
درايف لا يمنع التأطير بترويسة، لكن الملف بلا صلاحية وصول يعرض **إطاراً فارغاً
تماماً** بلا رسالة. ولا سبيل لاكتشاف ذلك برمجياً — الإطار من أصل مختلف. فالزر
والتنبيه هما المخرج الوحيد، لا تحسيناً اختيارياً.

## ٦. التعامل مع الأخطاء

`describeDataError` تترجم أخطاء PostgREST إلى رسائل عربية مفهومة، وأهمّ حالاتها
**«المنصة قيد التهيئة»** حين لا تكون السكيما مطبَّقة — فالمنصة قد تُنشر قبل تنفيذ
الترحيل، وعرض `relation does not exist` يوحي بعطل بينما هي تنتظر خطوة إعداد.
